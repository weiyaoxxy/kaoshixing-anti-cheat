01  方案机制与实现范围
原生考试窗口保持正常显示。动态库安装在被测捕获进程内：截取或连续取屏产生画面后，库复制图像缓
冲，将考试窗口对应区域填黑，再交给原接收对象。其他公共内容继续显示。
信任边界：原始考试像素已经进入被 hook 的远程进程地址空间，随后才复制并遮蔽。因此本方案改变其
既有回调 / 编码链收到的输出，不能证明不受信任的宿主从未取得原图，也不能抵御宿主主动绕过或读取原
始缓冲。
步骤 实现 本轮证据
1. 原生目标
NSWindow + 可编辑 NSTextField / 
NSTextView；按钮、滚动区、下拉框。
nativeUI=true；共享状态 readOnly；
captureProtectionEnabled=false。
2. 目标范围
目标写出 windowID、ownerPID、CoreGraphics 
bounds 配置。
只包含考试窗；独立公共窗口不在遮蔽范围内。
3. 进程内拦
截
C 入口用 dyld interpose；SCK 方法用 Objective-
C runtime 包装。
image_loaded、capture_call 和样本回调分别记录。
4. 复制与遮
蔽
复制 CGImage、BGRA CVPixelBuffer 或 
IOSurface；保留原输入。
目标单窗口输出为不透明黑图；桌面范围只覆盖目标
矩形。
5. 输出与复
核
转交原截图回调 / 流接收者，再核验实际输出。 公共 LIVE-TICK 变化用于排除冻结整个画面。
适用单位是捕获进程
库只影响实际加载它的进程。另一个未加载库的程序、已经存在而未受控的旧 Session，或未覆盖的捕获后
端，仍可能获取普通考试窗口。第 7 页的独立截图直接验证了这一边界。
不会自动继承的能力
窗口外的中文输入法候选、右键菜单、系统弹窗和其他敏感窗口不自动纳入目标矩形。新原生 Demo 未实
现自身录像编码，本轮没有完成客户端自录与回放验收，不能沿用上一版画布 Demo 的录像结论。
实现：Sources/CaptureHook/CaptureHook.m；目标：Sources/NativeExamDemo/main.swift。v1.2 库 SHA-256 为 
ce5f744b…3202f04；完整值见第 11 页。
