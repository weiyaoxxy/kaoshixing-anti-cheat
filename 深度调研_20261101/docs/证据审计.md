# 第一轮证据审计（只读复核）

本审计属于第二轮深度调研，原目录的报告和证据保持不变。审计脚本只读取第一轮资料，输出写入本目录。原始文档的 SHA-256 与逐条统计保存在 [original-evidence-audit.json](../research/evidence-audit/original-evidence-audit.json)，可用 [audit-original-evidence.py](../scripts/audit-original-evidence.py) 复核。

## 复核结论

第一轮“主矩阵 214 帧、protected 补测 126 帧、window-none 补测 123 帧，合计 463 个保存 PNG”的数量与原始记录一致。463 张来自 **18 个 SCStream 生命周期**，不是 463 次独立实验。本次独立复核未发现缺文件、额外旧 PNG、文件名重复、报告成功帧数与实际文件数不一致、非 complete 保存样本或流错误。每组捕获权限预检均为 true；既有分析记录覆盖了全部 463 张图片的 OCR 观察值。

本审计重新计算了所有流 PNG 的文件哈希，并校验原始帧元数据；读取既有 OCR 和像素分析结果，**没有把读取既有结果描述为重新执行 OCR**。原主报告已区分黑屏、透明图、API 失败、代表性 MP4 解码和人工确认，不需要为本次审计改写原文档。

| 审计项 | 观察结果 | 可以支持的结论 |
|---|---|---|
| 流样本数量 | 214 + 126 + 123 = 463；18 个流生命周期 | 原报告保存样本数量可复核 |
| 文件与报告对应 | 无缺图、无额外 PNG、成功计数一致 | 未发现旧图混入这些具体目录 |

## 必须保留的统计边界

**不能计算“463 次零泄漏”的独立成功率。** 这些图片在同一系统、同一机器、少数捕获配置与短时间窗口中产生，且部分窗口输出完全相同。样本有强相关性，不能用独立伯努利试验的置信区间估算产品泄漏概率。原矩阵每条流通常约 2 秒；同 filter 更新前后的时长不能替代切换应用、切换窗口、捕获先启动、最小化或睡眠恢复。

**标记未命中只针对该标记及本次观察。** 旧像素指标使用固定紫色标记 ROI；`markerObserved` 还使用覆盖率至少 50% 的阈值。第一轮原始结果确实是 0 或完整标记附近的值，所以阈值没有把已观察到的少量标记像素遮蔽掉；但未来不得把 1%–49% 的标记当作安全。应同时报告原始像素数、全图候选、局部区域与 OCR。题目其它部分泄露但秘密字符串/色块未泄露，也可能逃过该判据。

**公开对照的 OCR 并不是可靠的可见性检测器。** 第一轮已记录 `publicDetected` 在 baseline 也为 false，说明该字段存在漏识别。不能据此认定公共区或整个窗口消失。完全透明的窗口流则有 RGBA 像素证据；window-none 补测保留光标的帧不能称为整图全透明，原报告已经分开表述。

**自身录制与物理显示是不同证据。** writer 完成、接受帧数和代表帧解码能证明自有帧编码得到包含内容的视频；不证明每一帧都正确、不证明窗口回采豁免、不包含普通 overlay、输入法和系统菜单。约六分钟录像的尾部 `xyz1` 对 ASCII/退格提供结果证据。自动投递 14 个事件只导致共用回调计数增加 6，不能据此确认 B 选项鼠标点击；用户的物理显示/交互确认另行保存，不能与自动日志混同。

**阶段标签与帧产生时间应分开。** 旧 Probe 的 phase 是回调队列处理时的标签，更新请求/完成使用 host uptime，样本保留 PTS。原报告已注明回调标签不等于精确视频边界。第二轮涉及动态切换，应按时间对齐，并将边界附近样本单列，而非把它们扔掉后宣布稳定。

## 为什么第二轮不能直接复用旧 ROI 分析

旧 [analyze-results.py](../../scripts/analyze-results.py) 根据初始化窗口坐标与固定画布计算 ROI，以文件路径包含 `display` 判断整屏，以 `scDisplays[0]` 作为显示器坐标依据。对第一轮单屏、固定尺寸、窗口没有移动的实验，这与实际场景相符；对以下新场景则不足：

- 应用过滤器输出属于显示器坐标，`sck-stream-application` 名称却不会触发旧脚本的整屏分支。
- 矩形截图采用请求矩形作为原点和范围，不能默认等同旧窗口 filter 的布局。
- 移动、缩放、最小化、恢复与跨屏需要随时间更新窗口几何；以结束状态套在全部历史帧上会漏检或标记错误区域。
- 多显示器不保证目标屏幕是数组第一项；光标和桌面其它窗口也可能含相似紫色像素。
- 输出整个窗口透明时，应报告“没有窗口内容/透明”，不能描述为“只把考试区遮蔽”。

第二轮应保留全帧透明度、全图紫色计数与桌面噪声对照、逐帧秘密/native OCR，必要时辅以可靠的静态 ROI。动态状态结合 scenario 时间轴、样本 PTS 和捕获附件解释。任何明确秘密文字或匹配标记的阳性都应保留，不能被阶段边界或阈值过滤掉。
