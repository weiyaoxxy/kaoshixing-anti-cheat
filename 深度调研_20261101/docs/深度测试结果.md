# 深度测试结果

本报告只分析新目录 `deep-matrix-20261101T091019Z`。逐帧数据保存在各 case 的 `deep-analysis.json`、`deep-analysis-frames.csv` 和 `deep-ocr.jsonl`。原报告与证据未改写。

所有保存的流 PNG 均逐张解码并交给本轮 InspectMedia/Vision 执行 OCR；失败、缺图和无图单独保留。全图紫色像素用于观察候选变化，包含桌面噪声，不能单独认定题目泄漏或无泄漏。生命周期不套用静态窗口 ROI。

## 复核后的主要发现

本轮完成 **12 个 case、17 个 SCStream 生命周期、1,644 张流 PNG** 的逐帧检查；加上单帧、源帧和视频代表帧，共 **1,692 张 PNG**。另保留 4 个 `SCFrameStatus.suspended` 回调，合计 1,648 个流回调。所有保存帧与报告数量对应，无缺图或额外旧图，无图片解码/OCR 错误；11 个有外部捕获的 case 均具有真实授权且 Demo/Probe PID 不同。详见 [完整性检查](../artifacts/deep-matrix-20261101T091019Z/analysis-integrity-check.json)。这些是同机、同系统、相关样本，不是 1,644 次独立安全试验。

1. **新增静态路径支持受保护画布方案。** baseline 的 `CGDisplayCreateImage`、矩形截图、目标应用流、同进程 SCK 截图，以及系统区域录制的代表帧均可检出秘密；protected 对应样本未检出秘密且目标标记 ROI 为 0。protected 自录 MP4 的代表帧仍含秘密。`CGDisplayCreateImage` 是历史符号兼容实验，不改变它在现代 SDK 的支持状态。
2. **同进程没有自动得到系统截图豁免。** protected 的 `SCShareableContent.currentProcess + SCScreenshotManager` 返回有效图片，但题目未检出；原始帧编码的自录视频可见。两条路径已用实际产物区分。
3. **普通覆盖 UI 仍泄露。** mixed 应用流 22/22、显示器流 21/21 检出 `NATIVE-LEAK`；矩形、同进程截图和系统录制代表帧也检出该普通控件，秘密题目未检出。窗口流则为整个输出透明，与显示器/应用流的局部隐藏不同。
4. **运行中关闭/开启保护需要独立解释。** protection-toggle 显示器流在 baseline 稳态 30/30 检出秘密及本阶段 `PHASE-01-BASELINE`；重新开启保护后的稳态未检出。窗口流却 201/201 整图透明，连中间 baseline 阶段都不恢复，因此缺少同一流内的正对照，不能据其全部为零认定每次切换都已验证成功。
5. **`.none` 切换边界仍出现一张旧画面。** sharing-toggle 窗口流的 [frame-028.png](../artifacts/deep-matrix-20261101T091019Z/sharing-toggle-window/capture/sck-stream-window/frame-028.png) PTS 比 `after-window-none` 日志晚约 **1.05 ms**，图像仍显示 `PHASE-00-INITIAL` 的旧 baseline 内容，已人工查看图像。后续 `.none` 稳态两段各 30/30 透明；恢复 baseline 后有新的 PHASE-02/04 阳性。此现象保留为“切换边界收到旧画面”，不能宣称属性调用返回瞬间撤回全部先前帧，也不能冒称是 `.none` 稳态新内容泄露。时差是日志与样本时间之差，不是端到端显示延迟测量。
6. **最小化与隐藏的无样本不能当作防护通过。** protected 生命周期显示器流 200 帧未检出秘密；窗口流保存的 126 帧全部透明。相应 baseline 流在恢复/显示后检出新 `PHASE-02-RESTORE` / `PHASE-04-SHOW`，提供恢复路径正对照。窗口流在最小化/隐藏稳态没有回调/PNG，已在表中明确记为 0/0，而非“0 次泄漏”；各窗口流各有两个 suspended 回调。
7. **4×、60 fps 仅是短时合成 UI 压力观察。** 3600×2000 画布约 20 秒录制接受 1,195 帧、拒收 0，writer 完成；平均绘制/提交 4.66 ms、P95 5.53 ms，进程 ps CPU 均值约 30.0%、峰值 34.5%，RSS 峰值约 259.7 MiB。代表帧可解码识别秘密；没有进行整段逐帧视频验证、GPU/总系统功耗测量或生产 WebView 基准。

## 采集失败与覆盖边界

初次目录 `deep-matrix-20261101T090423Z` 的首例因附件中 `presenterOverlayContentRect=CGRect.null` 的无穷坐标导致 JSON 写出异常，未产出完整报告，**不计入以上有效样本**。故障目录原样保留。Probe 已保留非有限值字符串和字段说明，并在序列化前递归检查；通过无屏幕访问的 NaN/±Infinity/空矩形自测和权限预检后，整个矩阵在新目录重跑。没有删除失败产物或用它们补齐成功统计。

本轮全图紫色背景噪声通常为 71–72 像素；最小化动画/缩略图可以改变这部分像素，因此它们不自动等于题目泄漏。OCR 保留文字位置与置信度，PHASE token 用于区分阶段；OCR 漏识别仍可能存在。运行中保护切换的窗口流缺少阳性、约 10 fps 的采样间隔、平台仅一台 Mac，以及系统 MOV/自身 MP4 只解码代表帧，均保留为限制。本轮没有把先前用户的人工显示确认扩大为所有新生命周期状态的人眼验收。

## 解释边界

- baseline、保护关闭阶段是泄漏检测器的阳性对照。保护打开后的阳性必须保留并检查对应图片，不能被混入关闭保护阶段。
- 矩形截图、应用过滤器、窗口过滤器、显示器过滤器是不同测试路径，不能互相替代。
- 全图紫色像素可能来自桌面其它窗口；静态 case 的 ROI 数量和 OCR 用于复核。动态 case 保留原始图以便确定变化来自何处。
- 最小化、隐藏状态没有可见窗口内容属于场景状态；不能当作捕获保护强度证据。
- capture API 调用成功、输出黑/透明、writer 完成均不能单独证明完整防截图能力。
