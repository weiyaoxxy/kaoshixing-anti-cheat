# 视频完整性校验说明

本轮对12个自录MP4和3个系统区域录屏MOV做完整解码检查；语义/OCR内容仍只验证代表帧，不能混称“全视频内容逐帧验收”。

初次使用FFmpeg默认null输出时，9个文件出现null muxer的non-monotonically increasing DTS日志，但15个进程均返回0。因为该日志来自输出复用阶段，不能直接称原始H.264损坏。原始结果保留为矩阵根目录 `video-integrity-default-null.json`。

随后明确输出 `-fps_mode passthrough -enc_time_base demux`，对相同15个文件完整解码，未改变任何输入视频；全部返回0且无错误日志。同时通过ffprobe解码读取全部输入帧的best_effort_timestamp，15个文件的时间戳均严格递增，无frame probe错误。最终记录为 `video-integrity.json`。因此本机数据支持“完整码流可解码且输入时间戳递增”，首次报错不能归因于已证实的输入帧时间戳倒退；默认输出时间基转换是更符合复测结果的解释，而非已逆向确认的内部根因。

复核脚本为 `scripts/check-video-integrity.py`，保存输入帧数量、最小时间差、元数据、所有stderr及退出码。该检查不覆盖音频同步、每帧题目/作答语义、播放器对所有VFR配置的兼容性，也不证明物理显示帧率。
