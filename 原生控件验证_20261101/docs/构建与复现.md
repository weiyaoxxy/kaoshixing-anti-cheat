# 原生控件 Demo：构建与复现

日期：2026-11-01。本文按现有源码和落盘记录离线核对，没有启动 GUI、投递输入、取屏、操作 ToDesk/UU 或更改权限。用户当前要求暂不操作桌面；以下运行命令供未来重新安排交互测试时使用，不代表已执行新的实验。

## 1. 版本与运行环境

已测机器为 Apple Silicon、macOS 26.6.2（25G83）。脚本以 arm64、macOS 13.0 deployment target 和 Swift 5 语言模式编译。最低编译目标只说明构建配置，不证明 macOS 13 已通过本轮全部 API、ready 判定、编辑与捕获实验。

已测 App 的 bundle ID 为 `local.examcapture.nativecontrols`；Info.plist 的显示版本为 `0.1`，build 为 `1`。本轮内部代码修订字段为 `native-controls-v0.3`。源码和已测二进制的哈希见 [README](../README.md)；每个自动样本另存 `run-config.json` 与 `source-snapshot.swift`。重新构建可能改变二进制哈希，重测时必须记录新值，不将新产物冒充原已测二进制。

必要工具：Apple Command Line Tools / Xcode SDK、Python 3、Pillow，以及用于离线视频检查的 FFmpeg。现有视频检查脚本指向 `/opt/homebrew/bin/ffmpeg`、`ffprobe`，其他机器需先核对路径。本目录已包含用于本机的编译产物；应用采用 ad-hoc 签名，不是已签名公证的正式分发包。

在本目录运行：

分别生成 `build/NativeControlDemo.app`、`build/CaptureProbe`、`build/NativeInputProbe`。这些脚本会覆盖本目录对应构建产物；若需严格保留已测二进制，应先在项目副本中构建。它们不会改动父目录的旧 Demo 或旧文档。

输入源检查器与 OCR 检查器的独立构建方式如下；这是复现说明，本次离线整理未执行这些命令：

## 3. 架构与模式

控件树包括真实 `NSTextField`、复选框和按钮形式的 `NSButton`、`NSScrollView` 及其 `NSTextView`。raster 模式使用一个从未上屏的源 `NSWindow` 承载该树，源窗口初始位置为 `(-10000,-10000)`，sharing type 为 `.readOnly`。

绘制链路为：

```text
原生控件状态 / 真实 NSTextView field editor
    → NSView.cacheDisplay(in:to:) 得到位图
    → BGRA CVPixelBuffer
    → CMSampleBuffer + host-time PTS
    → AVSampleBufferDisplayLayer 显示

同一 CVPixelBuffer
    → AVAssetWriterInputPixelBufferAdaptor
    → H.264 / MP4 自录
```

默认逻辑画布是 900×500 point，在本机 2×缩放下对应 1800×1000 像素。上方普通顶栏、模式说明、录制按钮、系统输入法候选窗口均不属于这份原始考试帧。

| 参数 `--mode` | 行为 |
|---|---|
| `direct` | 控件树直接加入可见窗口，供正常原生界面作明文对照 |
| `raster-baseline` | 控件树留在隐藏源窗口，可见窗口显示无保护的视频帧 |
| `raster-protected` | 与 baseline 相同的渲染链，视频 Layer 的 `preventsCapture=true` |
| `mixed` | 受保护视频之外，再叠加普通 `NSTextField` 标签，检测覆盖控件泄露 |

代理 `ProxyView` 在 raster 模式中接收鼠标/键盘，经坐标命中和真实编辑器方法改变控件。双击选择单词、拖选由实际 `NSTextView` 保存选区；Tab 循环、按钮激活由代理路由。`NSTextInputClient` 代理转发组合文本和候选定位查询，但它没有把系统候选窗口转换成受保护图像。

插入光标通过真实编辑器的 `firstRect(forCharacterRange:)` 求位置后由代理补画；按钮键盘焦点轮廓也由代理补画。状态中的 `proxyCaretImplementation`、`proxyCaretRectCanvas`、`proxyCaretDrawn`、`proxyFocusIndicatorImplementation` 明示这些辅助部分。`--no-proxy-caret` 可禁用代理光标。`saveNativeFrame` 保存纯控件缓存，`saveFrame` 保存包含辅助绘制的实际原始视频帧。

隐藏源宿主不是安全策略。已确认它可能出现在 CG/SCK 枚举中；有些按 ID 调用返回 nil、错误或零有效帧。独立对照还表明源窗口曾上屏后再隐藏，SCK 可以读到此前内容。不能用“没有显示在桌面上”替代捕获测试。

## 4. 未来手工启动与停止

只有在可以暂时独占这台 Mac 的前台测试窗口、用户没有同时通过远程软件操作时，才运行下面的交互例子。每轮使用一个新的输出目录，不覆盖原证据。

```bash
open -n build/NativeControlDemo.app --args --mode raster-protected --duration 30 --output artifacts/manual-protected-NEW
```

此命令会打开保护模式，30 秒后退出；默认不录制。添加 `--record` 会自动录制自身原始帧：

```bash
open -n build/NativeControlDemo.app --args --mode raster-protected --record --duration 30 --output artifacts/manual-recording-NEW
```

`--duration 0` 表示不自动退出。应用上方“开始自身录制”按钮也可启动录像；关闭可见窗口会等待 `finishWriting` 完成 MP4 收尾。直接强制结束进程可能留下未完成录像，不应将其作为正常录制结果。

其他参数：`--fps 1...60` 设置定时器目标；`--scenario none` 是默认无自动操作；`--scenario native-actions` 会按计划调用原生编辑/动作方法，是程序化状态测试，不能当作 CGEvent 或真人交互测试。

应从新输出目录的 `demo-state.json` 获取实际 PID、主窗口 ID、源窗口 ID及 `controlGeometry` 坐标，不复用此前某轮的 PID 或截图坐标。

## 5. 权限与前台前置条件

仅显示自有控件图像、生成原始帧和录制自有帧不需要获取桌面屏幕录像权限。独立捕获探针需要相应的屏幕捕获授权。实际事件注入使用现有的辅助功能与事件投递权限；工具检查 `AXIsProcessTrusted` 和 `CGPreflightPostEventAccess`，不会替用户修改 TCC 数据库或主动申请权限。

`NativeInputProbe` 只接受 `local.examcapture.nativecontrols` / `NativeControlDemo`，拒绝任意其他进程。`--global` 路径在每次发事件前验证目标 Demo 仍是前台应用，并要求有可见的普通层级目标窗口。没有此前提时，它会输出 `refused` 和 `postedEventCount=0`；此时控件状态未改变不是“输入处理失败”，而是该项未实际执行。

前台应用变化、窗口不在 on-screen 列表、隐藏/最小化、Space/Stage Manager 或远控操作都可能使实验失去前置条件。需要结合 `local-NSEvent`、窗口 key/resign/miniaturize 日志和 `appActive/appHidden/windowKey/windowVisible` 解读。日志只能证明本 App 收到的事件，不能凭一次失焦认定由哪个远控软件或用户操作引起。

`posted_delivery_unverified` 仅表示事件已投递。应再核对真实编辑器文字、选区、控件状态、事件回调与实际帧。`--text` 的 Unicode 注入不验证中文输入法；拼音实验必须切到已启用输入源并通过虚拟字母键触发组合，结束后恢复原输入源。

## 6. 自动实验脚本（未来恢复桌面测试时使用）

以下脚本会启动、激活和操作 Demo，并调用取屏工具；本次离线整理没有执行。

| 脚本 | 目的 |
|---|---|
| `scripts/run-native-interaction.py` | 真实 CGEvent 文字替换、移动/删除、全选、复选框、按钮、滚动，与独立捕获和 AX 对照 |
| `scripts/run-native-keyboard.py` | 双击、拖选、Tab/Shift-Tab、Space、Return 附加用例 |
| `scripts/run-native-ime.py` | 当前已启用简体拼音输入源的真实组合/提交、组合期捕获，最后恢复输入源 |
| `scripts/run-native-continuous.py` | 持续窗口/显示器流中，程序化编辑及最小化/隐藏恢复阶段；存在脚本不等于本轮已执行 |

例如：

```bash
python3 scripts/run-native-interaction.py --modes direct raster-baseline raster-protected mixed --tag native-rerun
python3 scripts/run-native-keyboard.py

```

这些脚本通常直接运行 `.app` 内可执行文件，输出到带 UTC 时间戳的新目录；日期不依赖机器界面时区。每轮保留独立进程 ID、实际命令、源码与二进制哈希、ready 状态、捕获权限及原始图像。自动脚本的 ready 成功不替代本机人眼正常显示确认。

`run-native-continuous.py` 已提供未来实验入口；在没有相应落盘证据前必须标记待执行。它使用 file-command 修改原生状态，并不代表整个持续流期间都使用真实鼠标/键盘。

## 7. 控制文件协议

在当轮输出目录原子写入 `control-command.json`，应用每 0.15 秒检查一次不同的字符串 `id`。命令完成后写 `control-ack.json`，回显相同 ID 和当时状态。示例：

```json
{"id":"example-001","action":"setText","text":"INPUTSECRETEXAMPLE7H5T"}
```

常用动作包括 `focus`（可带 `control`）、`setText`、`select`（`location/length`）、`insert`、`delete`、`toggle`、`button`、`scroll`（`y`）、`focusNext`、`focusPrevious`、`activateFocused`、`saveFrame`、`saveNativeFrame`、`minimize/restore/hide/show` 和 `finish`。`setMarkedText/unmarkText` 是显式程序化组合控制，不能冒充真实输入法事件。

`showSource/hideSource` 只用于独立源窗口暴露对照。`showSource` 会将源窗口移到屏幕内，并永久设置 `sourceExposureTest=true`、`sourceWindowEverOrderedFront=true`；它不能混入“源窗口从未上屏”的主样本，也不能在正常保护测试中自动执行。

## 8. 帧率与性能指标的解释

默认 Timer 目标为 **20 fps**，即约每 50 ms 请求绘制。输入、焦点变化、控件动作、程序化命令和某些回调还会立即请求绘制，所以实际入文件的帧数可能高于每秒 20；主线程调度也可能使定时器回调变慢。该实现没有严格固定帧率整形，不能承诺稳定 20 fps。

以下来自 `native-final-v03-20261101T133147Z` 已保存录像的完整解码统计。平均数为“文件帧数 ÷ 文件时长”，不是屏幕实际刷新率或任意瞬间帧率：

| 模式 | 解码帧数 | 文件时长（秒） | 文件平均帧数/秒 |
|---|---:|---:|---:|
| direct | 456 | 19.590000 | 23.28 |
| raster-baseline | 584 | 22.326667 | 26.16 |
| raster-protected | 600 | 23.078333 | 26.00 |

证据为 `research/video-integrity.json`。对应三组 final state 的 `recordingDroppedFrames=0` 只表示 writer 接收分支未记录拒收，不代表每个定时目标都完成，也不代表每个显示帧都被物理屏幕呈现。

`renderMeanMS` / `renderP95MS` 覆盖当前 `render()` 中的控件缓存、像素转换、样本提交和录像追加调用耗时。本轮三组平均约 14.84–16.28 ms、P95 约 18.16–20.87 ms；它不包括完整显示扫描、远程编码传输和接收端展示延迟，不是端到端输入延迟。各组采样时长与交互负载不同，不应直接据此比较保护开关的性能成本。

## 9. 离线复核与尚未完成的工作

不操作桌面的离线任务包括阅读 JSON/源码、检查原始 PNG、OCR、解码已落盘 MP4、复核哈希和整理报告。重新运行分析工具会更新派生 JSON 或代表帧；若需要保留旧派生产物，先复制待分析目录。

```bash
python3 scripts/analyze-native-images.py artifacts/CASE --token edited=INPUTSECRETFINAL7H5T
python3 scripts/verify-native-videos.py artifacts/CASE
```

第二个脚本会写 `research/video-integrity.json`，其中内容只覆盖本次命令列出的 case；不要无意缩小原汇总范围。完整解码验证文件结构和时间戳，代表帧 OCR 仍只是内容抽样，不能声称逐帧语义审阅。

后续需重新安排桌面测试的项目包括：物理屏幕与真人连续交互确认；失去前台条件的 mixed 用例复测；持续捕获期间的编辑/生命周期矩阵；中文候选翻页、鼠标选词、退格与取消组合、长句、多行、焦点切换；其他输入法、系统菜单/弹窗、无障碍完整可用性、跨显示器、不同 macOS 与 Intel。当前已确认的候选窗泄露和源宿主生命周期反例不会因为补测完成而自动消失，需要另外的设计方案。

当前方案证明的是特定控件树在本机可被离屏绘制、编辑并通过受保护图层呈现。它尚不是任意 `NSWindow`、整个原生应用、任意网页或第三方应用的自动保护组件。
