# 原生控件验证：输入与图像分析工具

本工具只用于本目录的合成考试 Demo。未修改旧实验、TCC、系统输入法或用户剪贴板。默认调用不发送事件；所有 GUI 交互应由主测试流程明确触发。

## NativeInputProbe

构建：`bash scripts/build-input.sh`。可执行文件：`build/NativeInputProbe`。

先检查已有权限（不申请权限）：

```bash
build/NativeInputProbe --output artifacts/input-preflight.json
```

精确接受 `local.examcapture.nativecontrols` / `NativeControlDemo`，拒绝任意其他进程。已有权限必须同时满足 `AXIsProcessTrusted` 和 `CGPreflightPostEventAccess`。每个事件发送前都会重新验证目标进程身份。坐标使用 Quartz 全局 point，左上角为原点；Demo 的 `state.controlGeometry` 给出控件坐标，应以当次实际 state 为准。

调用形态（PID 和坐标替换为实际值）：

```bash
build/NativeInputProbe --pid 12345 --post --activate --click '500,400' --output artifacts/click.json
build/NativeInputProbe --pid 12345 --post --key a --flags command --output artifacts/select-all.json
build/NativeInputProbe --pid 12345 --post --text 'INPUT-SECRET-ABC' --output artifacts/type.json
build/NativeInputProbe --pid 12345 --post --key left --flags shift --output artifacts/select-left.json
build/NativeInputProbe --pid 12345 --post --key delete --output artifacts/delete.json
build/NativeInputProbe --pid 12345 --post --double-click '500,400' --output artifacts/double-click.json
build/NativeInputProbe --pid 12345 --post --drag '500,400,650,400' --output artifacts/drag.json
build/NativeInputProbe --pid 12345 --post --scroll -100 --scroll-at '700,600' --output artifacts/scroll.json
```

默认 `postToPid`。需要检查实际全局事件路径时，明确加 `--global --activate`；此模式每个事件前检查 Demo 是当前前台应用，否则立即终止。鼠标坐标必须在目标可见窗口内。`--click-offset` 使用相对目标窗口左上角坐标。可用 `--window-id` 精确指定本进程可见窗口，隐藏的原生源窗口不会成为注入目标。

`--flags` 支持 `command,shift,option,control`，作用于按键、鼠标和滚动，不作用于 `--text`。Unicode 文字通过 `keyboardSetUnicodeString` 注入；即使注入了中文，也**不能**算作中文输入法组合、候选选择或 marked text 验证。

本工具不读取剪贴板、不准备剪贴板。Cmd+C/V/X 默认拒绝，只有明确传入 `--allow-clipboard-shortcut` 才允许发送。若没有单独准备并隔离合成剪贴板实验，不应启用该选项。Cmd+Q/W、系统导航类快捷键也被拒绝。

返回 `posted_delivery_unverified` 只说明 CGEvent 已发送。必须结合应用的 `events`、真实文本值、选区、滚动状态与像素帧确认交互是否发生；不以发送成功代替编辑成功。

## AX 只读检查

```bash
build/NativeInputProbe --pid 12345 --ax-inspect --output artifacts/ax.json
```

检查同一受限 Demo 进程的 AX 树，最多深度 10、300 节点，记录 role、title、description、value、selectedText、focused 和 enabled。属性文本最多保留 2,000 字符，并标注截断。它不发送事件，不读取其他应用内容。

被授权的 AX 应用读取控件文字，与系统截图是否遮蔽属于不同通道。能读到合成文本需要报告为 AX 可读；有限树未发现文本也不能证明所有 AX 访问路径都被阻止。

## PNG 图像分析

```bash
python3 scripts/analyze-native-images.py artifacts/CASE --token edited=INPUT-SECRET-ABC
```

脚本调用复制到新目录的 `InspectMedia` 进行 Vision OCR。原二进制和源码来源、SHA-256 记录在 `research/inspector-provenance.json`。

默认分析全部 PNG，按路径区分外部捕获、同进程系统捕获、原始控件帧、自己的录像代表帧及待人工分类图像。标记包括 `EXAM-SECRET-7K9Q`、`NATIVE-EDIT-6T2W`、`INPUT-SECRET` 前缀、`NATIVE-LEAK-8R3T` 和 `PUBLIC-CONTROL-4M2P`。可以通过 `--token 名称=完整文本` 增加当次编辑后的精确标记。

每个 case 输出：

- `native-ocr-cache.jsonl`：以输入文件 SHA-256 缓存 OCR 原始结果。
- `native-image-analysis.jsonl`：逐图 OCR、实际像素尺寸、透明度及图像哈希。
- `native-image-summary.json`：分证据类型统计命中、错误及流帧清单完整性。

脚本同时检查 `capture/report.json` 等探针报告声明的保存帧，列出缺图、多图、重复文件名与保存数量不匹配。缺图、图像解码错误或 OCR 错误返回退出码 2。捕获失败/跳过项单列；不会被判成保护成功。视频完整解码需另行执行，不能由代表帧 OCR 代替。

## 工具自身检查

已构建输入工具，并执行无目标、无注入的权限预检。当前权限均为 true，见 `research/input-permission-preflight.json`。

图像分析工具用旧矩阵 baseline/protected/mixed 的三张真实截图独立 smoke：baseline 题目标记命中，protected 未检出题目，mixed 原生叠加标记命中；3 张图片无解码/OCR 错误。这组仅验证工具可用，不能计入本轮原生控件新实验样本。
