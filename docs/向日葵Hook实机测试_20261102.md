# 向日葵 Hook 实机测试

日期：2026-11-02；本地时间采用 Asia/Calcutta（UTC+05:30），证据文件保存 UTC。证据目录为 `artifacts/sunlogin-hook-test-20261102T121915Z`。

## 结论

**本轮没有验证成功向日葵的 Hook 加载或采集调用拦截。** 对实际测试的原版 **16.5.0 build 30905**，已在当前用户 Desktop 启动任务中配置 v1.4 库及 audit 参数，但初始实际进程映射未发现本项目库，实验目录在结束核验时没有产生 Hook 日志。因此没有进入 block 遮蔽阶段，不能宣称题目隐藏或远控阻断成功。

这只否定本轮所测的“原版用户级 Desktop，经 launchd 任务环境变量启动加载”结果，不证明所有向日葵版本、其他进程或其他注入方法都不可能成功。

**原任务已按时自动恢复；用户彻底关闭旧远控窗口、重新连接后，确认两个测试窗口恢复正常。** 中途确实出现本机与远端画面不一致，不能把任务恢复等同于远端会话已立即恢复。原始实验进程已经退出，当前用户 GUI/Desktop 未观察到本项目已知 Hook 文件映射；自有测试窗口已正常关闭。

汇总见[结构化结果](../artifacts/sunlogin-hook-test-20261102T121915Z/result-summary.json)。

## 3. 能观察到什么采集线索

当前 Desktop 映射含 `ScreenCaptureKit`、`VideoToolbox`、`sl-client-desktop.dylib`。对当前 `Contents/Resources/plugins/sl-client-desktop.dylib` 的补充只读检查发现 `SCStream`、`SCShareableContent`、共享内容枚举、启动及帧回调相关导入／选择器，同时有 CGDisplayStream、传统 CoreGraphics 截图、IOSurface、VideoToolbox 编码接口。插件 SHA-256 为 `0f9f02ef899a157587959c865cd0c7c74e77cbfbb993d560a62d95b0570d0bcd`，严格签名检查通过；[新版候选机器记录](../artifacts/sunlogin-hook-test-20261102T121915Z/current-version-capture-candidates.json)保留了其中 SCStream、CGDisplayStream 和编码等关键导入，不将静态导入升级成实际调用。

这些是 SCK／CG 路线的**候选依据**。最初只检查主要可执行文件得到的 CG 线索不覆盖这个插件，不能据此断言旧版或新版只有 CG 路线。

基线外部样本记录了 `-[VideoToolboxEncoder encode:time:tick:error:]`、`VTCompressionSessionEncodeFrame` 与 IOSurface 符号，前后进程身份一致。它支持 Desktop 中存在画面处理／编码活动，**没有建立完整采集入口到某一帧的关联，更不是我们的 Hook 命中证据**。原始 sample 已删除，仅保留哈希及最小已知符号记录；部分记录可能来自汇总段，不把所有行拼成同一调用链。[基线外部诊断](../artifacts/sunlogin-hook-test-20261102T121915Z/baseline-desktop-sample.json)。

## 4. 恢复与环境核验

控制器只临时替换 `gui/501/com.oray.awesun.desktopagent` 的运行定义，源文件仍为 `/Library/LaunchAgents/com.oray.awesun.agent.plist`；实验使用原版 Desktop 程序，没有修改或重签 app。root Service／Helper 没有被本控制器停止或注入，audit 前后其进程身份一致。

deadline 触发了同一控制器中的串行恢复，任务卸载、原定义重新注册及运行检查通过。原 Desktop 71610 已退出；新 Desktop 72977 从正式定义运行。受检 11 项文件的哈希与 audit 前一致；GUI 和 Desktop 的 vmmap 均成功、身份稳定、未见 `libCaptureHook`／`libLoadWitness` 文件名。[恢复控制记录](../artifacts/sunlogin-hook-test-20261102T121915Z/audit/result.json)、[独立恢复复核](../artifacts/sunlogin-hook-test-20261102T121915Z/post-restore-verification.json)。

文件名匹配不是通用内存完整性证明；本地日志可修改，也不是对抗最高权限的远程证明。控制器自身读取 root 进程身份有权限限制，未伪造完整枚举；独立原生清单补充了本轮 root 进程的身份复核。

用户随后报告“两边不一致”：本机截图可见测试窗口，远端照片只见桌面，菜单栏时间看似停在更早的 18:12。该时刻与桌面组件恢复重启接近，但尚不能据此证明因果。完全关闭远端会话窗口、重新连接后，用户确认“重连后两个测试窗口都正常了”。结果与旧会话停帧的假设相符，未单独证明底层原因；没有把这种画面不一致记作 Hook 遮蔽成功。[恢复异常记录](../artifacts/sunlogin-hook-test-20261102T121915Z/recovery-mismatch-observation.json)、[最终远端恢复确认](../artifacts/sunlogin-hook-test-20261102T121915Z/recovery-human-observation.json)。

后续只读排查确认当前只有一个内建活动显示器、无镜像；目标相关统一日志未取得明确 ScreenCapture 授权或拒绝结论，权限状态仍为未知。恢复后 Desktop 的一次三秒样本未观察到所筛选的编码／采集符号；采样阴性不能证明从未采集，也不能独立定位冻结原因。[诊断摘要](../artifacts/sunlogin-hook-test-20261102T121915Z/recovery-diagnostics.json)、[恢复异常期间样本](../artifacts/sunlogin-hook-test-20261102T121915Z/post-restore-mismatch-sample.json)。

最终只对自有 `SunloginRemoteProbe` 验证 PID、UID、出生身份和精确可执行路径后发送正常退出请求；探针保存 inactive，Hook 目标配置保存 enabled=false，未向向日葵发送终止请求。[测试窗口清理](../artifacts/sunlogin-hook-test-20261102T121915Z/probe-cleanup.json)。
