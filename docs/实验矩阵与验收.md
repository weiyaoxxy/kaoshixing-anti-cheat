# 实验矩阵与验收

本矩阵区分“已执行”“未执行”和“需要资格/设备”。事实结果见 [本机测试结果](本机测试结果.md)，原始记录见 `artifacts/`。本次不是覆盖所有 macOS 的认证。

## 1. 本机核心矩阵

五模式分别是 baseline、window-none、protected、both、mixed，详见 [PoC设计](PoC设计与复现.md)。每个模式是新启动的考试进程，敏感内容显示前设置对应属性。捕获工具是独立进程，目标按精确 windowID 指定。

| 捕获/观察路径 | 五模式执行 | 主要判据 | 必须保留的区别 |
|---|---|---|---|
| 用户看本机物理屏幕 | protected 人工确认 | 题干/选项可见，输入反馈 | 系统截图/远程画面不能替代人眼；人工陈述和事件日志分别记录 |
| `/usr/sbin/screencapture -l ID` | 已执行 | 保存图像及试题标记 | none/both 的错误是无有效样本，不是保护通过 |
| `/usr/sbin/screencapture` 整屏 | 已执行 | 目标区域与背景/公开区 | 不把这个 CLI 等同于所有截图快捷键路径 |
| CGWindowListCreateImage 单窗口 | 已执行，动态兼容调用 | 目标有效像素与权限正对照 | 现代 SDK 已 obsoleted，运行时成功不代表支持契约 |
| CGWindowListCreateImage 整屏合成 | 已执行，动态兼容调用 | 屏幕目标 ROI 内是否泄露 | 文件名 cg-display 并不是调用 CGDisplayCreateImage |
| SCScreenshotManager 窗口 filter | 已执行 | 秘密区域与普通公开控件 | 单张输出不外推到 SCStream |
| SCScreenshotManager 显示器 filter | 已执行 | 屏幕 ROI、题目、原生 overlay | 必须确认没有被其他窗口遮挡 |
| SCStream 独立窗口 | 已执行，连续多帧 | complete 状态、原始 RGBA、OCR、标记 ROI | 全透明整窗单列；不能声称一定只有题区被遮蔽 |
| SCStream 显示器 | 已执行，连续多帧 | 逐帧秘密与原生 overlay | 不只检查第一帧 |
| SCStream 更新相同 filter、stop 后新建 | protected、window-none 已追加执行 | 阶段事件、PTS、全部帧 | 回调时间不等于精确视频时间边界；仍需不同 filter/窗口切换测试 |
| 自身原始帧 MP4 | 五模式已执行 | writer完成、实际解码、秘密文字/图案 | 不等于自身通过系统屏幕捕获享有豁免 |
| 原生 NSTextField 覆盖受保护 Layer | mixed 已执行 | 黄色 NATIVE-LEAK 是否出现在捕获中 | 证实普通控件需纳入敏感渲染面 |

原始帧图有 `EXAM-SECRET-7K9Q` 与紫色色块；公开顶部有 `PUBLIC-CONTROL-4M2P`；混合控件有 `NATIVE-LEAK-8R3T`。OCR 对中文/英文混排可能漏识别，因此公开标记 OCR=false 不直接判定公开区域不存在；结合图像、人眼检查和像素 ROI。任何关键捕获失败必须修复或保留为无效样本，不准按“抓不到＝防住”填表。

## 4. 验收原则

- 首先满足本机可见和输入正确；若保护让本地试题也不可见，不能算成功。
- 每条外部路径都有权限和有效的 baseline；保护模式检查实际像素，并记录黑色、透明、背景替换、跳过、错误的差别。
- 最少覆盖启动前、中途、结束后多个时段；不能只拿一张截图交付安全承诺。
- 自身录制必须完成并实际解码；检查对应题目/答案状态/时间戳。不要只确认文件存在或编码器返回成功。
- 按所支持系统和设备逐个出报告。未执行的格子保持“未验证”，推断单独标注，不能由邻近测试自动填“通过”。
- 输入法、辅助功能、文件副本、原始帧内存、外部相机属于不同泄露渠道；需要产品威胁模型，不要把视觉捕获保护扩大解释成对任何其他进程都不可获得题目。
