日期：2026-11-03；以下本地时间使用用户时区 Asia/Calcutta（UTC+05:30）。

**结论：在本机只读检查中，ToDesk、UU、向日葵三家都检出了实际运行且通过厂商组件签名要求的进程。此层检测不需要 Hook 注入，也不需要另一台设备发起连接。若考试禁止这些软件运行，本轮结果应建议阻止开考。**

## 3. 新增实现

- [原生进程清单](../Hook新方案_20261101/Sources/RemoteProcessInventory/main.swift)：读取真实执行路径、PID/UID/父进程/出生时间；两次核验身份；提供指定 PID 复核；通过只读 sysctl fallback 处理部分 root 服务身份读取。
- [厂商组件策略](../Hook新方案_20261101/Sources/RemoteProcessInventory/policy.json)：固定本轮已确认的 Team ID 和精确组件 Identifier。相同厂商的其他产品不因 Team ID 相同自动算远控。
- [检测与核验脚本](../Hook新方案_20261101/scripts/detect-remote-processes.py)：执行静态代码要求核验、文件前后身份检查和进程再次复核；输出各软件结果、未知项和仅供参考的考试准入建议。
- [构建与使用说明](../Hook新方案_20261101/Sources/RemoteProcessInventory/README.md)：输出新目录，不覆盖旧 Demo 或历史库；原生返回码 2 的不完整结果仍保留。

已有 NativeExamDemo 界面、UU Hook 检查器和运行中的远控均未被新工具替换。新检测入口独立于 Hook；将其接入考前准备页和考中守护是后续功能。

## 4. 误报、生命周期与错误处理验证

18 项纯逻辑单测通过，覆盖：精确厂商/组件身份、同厂商其他软件、同名未签名程序、PID 重用、UID/路径变化、正常父进程变化、进程退出、文件变化、验签权限不足、枚举失败、仅辅助组件、否定结果边界和运行期间输入变化。策略从同一份启动字节解析并计算哈希，结束时另核对变化，避免将结束时的新文件哈希误写成本轮实际输入。[测试源码](../Hook新方案_20261101/tests/test_remote_process_detection.py)、[本轮测试记录](../artifacts/remote-process-detection-20261103/unit-test-final.json)。

另实际启动一个自有合成程序，文件名为 `UURemote`，只短暂存活后自然退出：

1. 原生清单能发现这个名称候选。
2. 它没有网易 Team ID 和组件签名，因此只记 `candidateUnconfirmed`，没有误认成已核验的 UU。
3. 存活时出生身份复核一致；自然退出后指定 PID 返回无身份/无法确认，没有继续信任旧 PID。

该程序不是网易 UU，没有控制界面、采集或网络行为，也没有向它或远控发送信号。证据：[合成程序集成验证](../artifacts/remote-process-detection-20261103/fixture/README.md)。

开发阶段还发现 `codesign -R` 内联要求需要 `=` 前缀的问题，已修复并加入参数和工具错误分类回归。初次结果保存在 `live-verified/`，属于检测器调用错误，不计为软件验签失败或正式通过。`live-verified-v2/` 是参数修复后的三轮同结论检查；补齐输入哈希绑定后的最终证据使用 `live-final/`。

## 5. 本轮没有证明的事项

- 正式各轮有 52 个 PID 的实际路径无法读取，虽然已发现的 11 个候选身份稳定，仍保留 `enumerationComplete=false`。不能把它改成“全系统没有遗漏”，也不能推断这些不可读进程都是远控。
- 正结果证明受检组件运行，不证明另一台设备已连接、有人正在操作或发生作弊。Hook 是否加载、实际传出的画面均未在本轮检查。
- 静态签名核验绑定磁盘文件，不是对运行内存的远程可信证明；检测器和策略目前仍是本地测试文件。完全改名且移出识别路径、其他厂商、很短的进程生命周期未获完整覆盖。
- 检查按顺序进行，不是原子系统快照。每次外部命令有超时，整轮尚无统一截止预算；本轮约 4 秒不是耗时上界。不能把它当成 250 毫秒处置通道，更不能当执行前拒绝机制。
- 未通过真实关闭/重新启动三款软件验证生命周期；本轮用自有合成进程验证同名误报与退出处理。三家真实启动/退出、后台自动重启、强退、考试准入和结束恢复仍需独立验收。

第一层可据此落地的行为是：**在已支持且可核验的范围内发现远控组件正在运行，明确列出原因；若有检查缺口，保持“无法确认”，不能放行为“无远控”。**
