# 考试客户端与 UU Hook 检测：实现及验证

已在原生考试 Demo 中实现两项检测，生成独立构建 `Hook新方案_20261101/build/NativeExamIntegrityDemo.app`。原有 Demo（PID 89885）仍运行旧版本，未被替换；UU 保持正式原版运行。本次没有对 UU 注入、重签、停止、重启或修改配置。

## 已实现的行为

1. 客户端启动后、每 5 秒由独立定时器发起检查。观察动态库加载、加载环境变量、动态/静态代码签名，以及四个关键 ObjC 方法的实现归属、地址和入口字节变化。检查失败与发现异常分开，不能读取时不显示正常。
2. 一旦发现异常，界面标记“发现异常，已标记待复核”；本次运行期间持续保留，方法或文件恢复后不清除。记录 sessionID、PID、时间、序号、检查状态变化和具体证据。
3. UU 按 GUI / Service / Server / Daemon 识别真实进程，关联 PID、启动时间和路径，读取当前可执行模块映射。可报告已发现已知 Hook 名称、未发现已知 Hook、未知或未运行；记录状态变化历史。
4. 所有检测与磁盘写入均在后台完成，界面从回调更新状态。安全扫描不依赖被监测的界面 `tick()`，避免该方法被替换后连带停止检测。

输出为 `integrity-status.json`、`integrity-events.jsonl`、`uu-hook-status.json`、`uu-hook-events.jsonl`，并汇入现有 `state.json`。日志写入失败也明确反馈，但磁盘不可写时不能承诺落盘留证。

## 测试结果

第一批 8 个客户端场景全部通过；完成独立调度修复和最终 UU 集成后，正常无窗口检查、原生界面更新和 GUI tick 被替换这 3 项回归全部通过。合计覆盖 9 个不同场景。

| 场景 | 观测结果 |
| --- | --- |
| 正常启动 | 无异常发现；开发签名的发行身份保持未知 |
| 启动时加载自有测试 dylib | 发现非预期模块与加载环境变量，标记待复核 |
| 运行中替换方法后恢复 | 发现实现归属/地址变化；恢复后异常仍保留 |
| 运行中加载后立即卸载自有 dylib | 下轮仍可从加载历史识别该模块 |
| 修改 bundle 的 Info.plist 后恢复 | 发现签名校验失败；校验恢复有效后仍保留异常 |
| 修改后重新 ad-hoc 签名 | 本地封装有效，但发行身份未知；不声称已验证原版 |
| 输出目录临时不可写 | 回调报告 recordingError / checksIncomplete；恢复后仍保留错误信息 |
| 原生界面自动更新 | 状态、原生字段、计数和正常退出均保持工作 |
| 将 GUI tick 替换为 no-op | tick 停在 1；安全检查继续至约 10 秒，并记录 tick 实现改变 |

UU 独立模块的 37 项自有测试、7 项本机只读检查通过。自有测试进程加载无行为的 fixture，验证实际 vmmap 的正例解析；没有将 fixture 加载进 UU。涵盖权限失败、超时、输出截断、PID 重用、进程身份核验、普通文件映射误报、witness 区分、历史变化去重和管道读取。

| GUI | 40406 | 可读取，未发现已知 Hook |

## 结论边界

**UU 的“加载”与“拦截有效”分开。** 当前依据可执行模块映射中的已知文件名，不能认证库内容或正确版本；改名库、同名伪造库、其他注入方式存在漏报/误报边界。`actualHookInvocationVerified=false`、`captureBlockingVerified=false` 始终明确保留；必须结合当前捕获调用及画面效果，才能说明实际拦截。

**客户端结果是本地异常线索。** 默认 Demo 使用 ad-hoc 签名，没有固定可信发行方，检查状态为 `incomplete`。已经验证：修改后重新临时签名可以通过本地封装校验。生产可嵌入预期 Apple Team ID 并使用正式签名，但客户端检测器本身仍可被完全控制电脑的人替换；目前没有服务端接收、心跳或远程可信证明。

监测覆盖已实现的加载路径和指定方法，不保证发现所有 Hook、启动前的所有修改或最高权限的绕过。方法及签名按间隔采样，检查间隙内短暂修改也可能未被发现；dyld 历史可以保留监测启动后加载并卸载的模块，但不能追溯监测启动前已卸载的模块。异常用于人工复核，不能自动等同于作弊。

Apple 文档说明动态签名校验的范围是身份验证所需组件；它不等于扫描全部进程内存：[SecCodeCheckValidity](https://developer.apple.com/documentation/security/seccodecheckvalidity(_:_:_:))。Hardened Runtime 可用于减少部分代码注入途径，当前检测构建未将其自动开启：[Hardened Runtime](https://developer.apple.com/documentation/security/hardened-runtime)。
