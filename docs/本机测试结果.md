# 本机测试结果

## 已取得的结果

在本机 **macOS 26.6.2（25G83）、Apple Silicon** 上，`AVSampleBufferDisplayLayer.preventsCapture = true` 的 PoC 已显示出可用性：独立捕获进程保存的系统截图、ScreenCaptureKit 截图和持续流中，没有检出合成考试内容的秘密标记；客户端自己编码出的 MP4 可以解码并识别该标记。用户另外确认了物理屏幕显示和交互正常。这支持继续采用“原始帧分别送入受保护显示与自有编码器”的架构，不等于所有 macOS、所有捕获软件和所有状态均已防护成功。

**用户人工确认**：“本机可见完整题目，点击和输入正常”。记录时间为 2026-11-01 14:01:58（Asia/Kolkata），对应 `artifacts/interactive-validation/human-verification.json`。它确认 protected 模式的本机显示及交互体验。**人工回复当时**快照的 `inputEvents` 为 0；**随后 14:03:44 的定向自动事件实验**使该计数从 0 增至 6，且录制尾部识别到 `xyz1`，证明 ASCII 输入与退格结果。这些自动事件不能算作先前人工点击的日志佐证，定向自动鼠标点击仍未确认。`displayVerifiedByHuman=false` 是 Demo 固定诊断字段，程序没有擅自修改为 true。人工声明与自动数据分别保存。

普通 UI 不会自动继承保护：mixed 模式中，放在视频层上方的普通 `NSTextField` 的 `NATIVE-LEAK-8R3T` 在六种单帧截图，以及显示器流的 **22/22 帧**中可由 OCR 识别。不能把题干、答案或其他敏感提示继续放在普通控件里。

### 系统截图与 CoreGraphics 的失败／兼容边界

window-none 与 both 下的 `screencapture -l` 返回码为 1，stderr 为 `could not create image from window`，且没有生成窗口 PNG。这两格明确保留为无有效图。

CoreGraphics 五组模式均实际生成 PNG，未因 NULL 被误计为保护成功。其中 window-none、both 的窗口 PNG 全透明。Probe 通过 `dlsym` 调用仍导出的公开旧符号 `CGWindowListCreateImage`，是对本机兼容行为的实验；该 API 在 SDK 中已标 macOS 15 obsoleted，不构成现代部署支持承诺。**`cg-display.png` 也是 `CGWindowListCreateImage` 的显示器范围合成，本次没有调用 `CGDisplayCreateImage`。**

系统命令行截图也不自动等于已经操作并验证了 Cmd-Shift-3、Cmd-Shift-4、Cmd-Shift-5 或 QuickTime 的所有入口。

## 逐帧标记检查

Demo 在考试帧中绘制固定 88×64 point 紫色矩形，在 2× 输出下为 **176×128＝22,528 pixel**。分析使用 Pillow 解码实际 PNG，在已知画布和窗口坐标映射出的 ROI 内统计 `R≥190、G≤90、B≥190、A≥200` 像素，同时单独保留 Vision OCR 的 Boolean 值。系统窗口截图含非对称阴影，ROI 由明文 baseline 标记校准；其余窗口／显示器 ROI 根据日志中的窗口与屏幕几何计算。

| 模式 | 窗口流帧数 | 每帧标记 ROI 像素数 | 显示器流帧数 | 每帧标记 ROI 像素数 | 秘密 OCR 命中数 |
|---|---:|---:|---:|---:|---:|
| baseline | 22 | 每帧 22,528 | 21 | 每帧 22,528 | 43/43 |
| window-none | 21 | 每帧 0 | 21 | 每帧 0 | 0/42 |
| protected | 21 | 每帧 0 | 22 | 每帧 0 | 0/43 |
| both | 22 | 每帧 0 | 21 | 每帧 0 | 0/43 |
| mixed | 21 | 每帧 0 | 22 | 每帧 0 | 0/43 |

全屏图在考试窗口之外存在约 71–72 个相似紫色像素，分析未将这些桌面像素当作题目泄露。`analysis-images.csv` 同时保留全图与 ROI 数量，便于审计判据。

原始 `media-inspection.jsonl` 只检查了每条流的第一帧；此次补充 `stream-inspection.jsonl` 对**每条流的每一张保存 PNG**执行 OCR。自动字段 `publicDetected` 在 baseline 中也为 false，源于公开对照文本被 OCR 错识；不能拿这个字段判断公开控件是否实际消失。敏感标记与 native leak 标记则有明确的阳性对照。OCR 未命中自身仍不能证明其它文字没有泄露，需配合像素、界面范围和后续更多测试。

## 自身录制与性能记录

五组均生成结束写入的 MP4，`writerStatus=2`、writerError 为空；录制帧数为 baseline 360、window-none 360、protected 360、both 361、mixed 360，记录的编码器拒收帧为 0。视频时长约 17.98–18.02 秒。分别通过 AVFoundation 解码约第 1 秒画面，五组均 OCR 命中秘密标记，1800×1000 分辨率正确。紫色 ROI 代表帧约 22,225 个符合阈值的像素，差异与有损编码相符；没有把“MP4 文件存在”当作录制内容正确的唯一证据。

这是对原始绘制帧编码，**不是通过系统录屏 API 取得保护窗口的豁免**。mixed 的普通覆盖控件不在原始帧里，所以该控件不在自录 MP4 中；桌面遮挡、窗口外输入法和系统菜单同样不自动包含。主矩阵尚未逐帧解码整段 MP4，也未测音频、音画同步、磁盘满、长时录制。

另外，交互验证实例的 `self-recording-FB55D674.mp4` 已完成写入：时长 **372.573 秒**，`writerStatus=2`、writerError 为空，记录接受 7,457 帧、拒收 0 帧。`tail-inspection.jsonl` 保存了 **370.573 秒**处的真实解码与 OCR：包含 `EXAM-SECRET-7K9Q` 和 `(ASCII): xyz1`。这把输入状态与最终录制内容联系起来，但仍没有逐帧验证整段约 6 分钟视频。

定向事件工具只向 Demo PID 发送事件，记录 14 次 down/up 投递，对应计划中的一次点击、5 个 ASCII 字符和一次退格。Demo 回调计数实际增加 **6**，少于计划的 7；该计数不区分事件类别，不能据此宣称鼠标点击已到达或选项 B 已选中。尾部 `xyz1` 为键盘输入及退格提供独立输出证据；鼠标正常目前依据用户人工声明。证据保存在 `input-events.json`、最终 `demo-state.json` 与 `tail-inspection.jsonl`，不把投递工具退出成功本身当作输入送达证明。

## 复核命令与产物

```sh
python3 scripts/analyze-results.py artifacts/matrix-20261101T082724Z
python3 scripts/analyze-results.py artifacts/filter-update-protected \
  --state artifacts/filter-update-protected/demo-state-at-human-confirmation.json
```
