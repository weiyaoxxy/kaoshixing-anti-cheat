# UU Hook 受阻后的系统防护路线：Apple 官方资料核验

核验日期：2026-11-02，Asia/Calcutta。仅研究公开官方资料和本机 SDK 头文件；未申请 entitlement、联系厂商、安装系统扩展、注册后台服务或改变 UU 状态。本机项目运行基线为 macOS 26.6.2；本次 `xcrun --show-sdk-version` 实际返回 **26.5**。

**建议优先把 AAC 作为完整考试会话的系统防护候选，把 Endpoint Security 作为“限制新进程执行”的候选。两者都需要授权与实测。普通 root helper、MDM 设置以及本地 Hook 实验，各有不同作用，不能互相替代。**

## 2. AAC 的可行方向与版本边界

AAC 适合“考试期间建立受限制会话”的目标。可以先接入考试开始、结束、失败、中断状态机，再对 UU 做真实连接对照。A1 的能力说明有价值，但不是对所有第三方远控实现、所有历史与未来版本、物理采集或已被篡改操作系统的覆盖保证。

对本机 macOS 26.6.2，可以依据 A1 把屏幕共享/镜像、截图与屏幕捕获、Remote Login 列为官方描述的考试模式限制目标；本项目尚未在获授权 AAC 会话中验证这些行为。尤其没有取得“进入会话前已经连接的第三方 UU 一定被断开”的厂商保证；它可能涉及帧停止、捕获失败、网络变化或会话中断，必须实测确认具体结果。

参与应用和参与应用联网可分别配置；[AEAssessmentParticipantConfiguration](https://developer.apple.com/documentation/automaticassessmentconfiguration/aeassessmentparticipantconfiguration) 列出 `allowsNetworkAccess`。因此应确认监考上传、考试 API、辅助应用和网络代理在实际策略下是否仍可用。白名单需要最小化，并保留参与应用的签名检查。

本次核验没有找到名为 `allowsScreenCapture` 的公开 AAC 属性；对应猜测 URL 返回 404，本机 `AEAssessmentConfiguration.h` 也没有此符号。查到的是 A5 的 `allowsScreenshots`，其范围仅为剪贴板截图。不能用该属性保证“自有监考程序可以录全屏、其他程序不能录屏”。从自有原始渲染帧编码录像是不同的技术路径，其与 AAC 的兼容性仍需验证。

配置总览中的部分说明仍将非参与应用的例外概括为仅 iOS/iPadOS，但新属性页面已经列出 Mac 上的具体例外。实现和方案承诺应核对每个符号的 availability，而不是以这段旧概括排除全部 Mac 可配置项。

macOS 27 的属性必须用版本判断和对应 SDK 编译。最新属性文档使用 [`allowsOnlyParticipantsToRun`](https://developer.apple.com/documentation/automaticassessmentconfiguration/aeassessmentconfiguration/allowsonlyparticipantstorun)；WWDC26 示例拼写是 `allowOnlyParticipantsToRun`，实现时应以所用 SDK 和属性文档为准，不能直接照搬视频示例。

特别重要的是 [`requiresSIP`](https://developer.apple.com/documentation/automaticassessmentconfiguration/aeassessmentconfiguration/requiressip) 的官方限制：当用户有管理员权限时，框架可能不能可靠判断 SIP 是否开启；这个要求也不能证明 SIP 过去被关闭期间系统未被修改。因此这类检查不构成对管理员控制终端的完整远程证明。新属性页面标注 macOS 27+，本机 SDK 未包含该属性。

不应把自动结束会话与强行结束进程混为一谈。A3 的生命周期要求可直接转成产品规则：等待开始回调才显示试题；结束时先隐藏试题，再请求结束并等回调；中断时进入异常状态，停止继续出题。崩溃、强制终止、注销、重启等场景仍要独立测试，不能仅依赖正常退出路径。

## 3. Endpoint Security：限制新执行与记录事实

[`ES_EVENT_TYPE_AUTH_EXEC`](https://developer.apple.com/documentation/endpointsecurity/es_event_type_auth_exec) 对应执行新映像前的授权请求。它适合对已识别的远控组件执行策略，并记录执行身份和结果。**它本身不会关闭已运行的 UU Server、撤销既有远控会话，或阻止一个已经运行的通用进程通过其他方式继续通信。** 这些属于独立的会话处置与覆盖问题。

ES 接入需要 Apple 批准 `com.apple.developer.endpoint-security.client`，还需要 FDA；若作为系统扩展部署，另有容器安装能力、用户批准或受管部署配置。当前官方 [`es_new_client`](https://developer.apple.com/documentation/endpointsecurity/es_new_client(_:_:)) 与 [ES entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.endpoint-security.client) 继续明确授权要求。

E1 中 Apple 说明 ES 系统扩展及资产有 SIP 保护，并对其 launchd job 提供包括阻止 root 直接卸载在内的额外保护。**该结论限于相应系统扩展部署形态与系统安全前提，不能套给普通 SMAppService daemon 或当前项目的用户级 job。** 它仍不能阻止电脑所有者断电或保证异常一定上传到服务器。

E1 还说明 AUTH 响应有截止期限，超时会终止客户端；该讲解中的超时行为为隐式允许。因此策略处理应在本地及时完成，不能等待云端网络请求才回复授权。此处资料来自 WWDC20，生产实现应复核目标 OS 的最新 API/SDK 行为并做负载、超时、重启测试，不能宣传“组件坏了也一定继续阻断”。

## 4. SMAppService 和 MDM 的位置

SMAppService 可用于正规安装独立后台组件、状态检查和恢复逻辑。Apple DTS 在 [Privileged helper with SMAppService](https://developer.apple.com/forums/thread/739940) 中说明，需要提升权限的场景应使用 daemon 路径。应把 root 权限用于必要的受控操作，并设计明确的 IPC 身份校验、最小命令范围和恢复事务。

[`SMAppService.Status.requiresApproval`](https://developer.apple.com/documentation/servicemanagement/smappservice/status-swift.enum/requiresapproval) 也明确用户撤销运行同意后会返回该状态。故普通 helper 适合提高可靠性和分离职责，但不能作为“用户拥有管理员权限仍永远不能停用”的保证。

MDM 更适合机构管理的设备。M1 的 Screen sharing 条目是禁止启用系统屏幕共享；Remote Desktop 条目是限制相应设置修改；截图/录屏条目有自身范围。对 UU 的结论必须建立在它实际使用的 API、权限与服务路径以及测试结果上。也不能把 MDM 所有配置能力默认带到未注册管理的考生个人电脑。

## 5. 补充：macOS 27 App Attest

[Secure your apps with App Attest，WWDC26](https://developer.apple.com/videos/play/wwdc2026/201/) 明确说明 App Attest 从 macOS 27 开始支持 Mac，调用时还要检查 `isSupported`。视频说明服务端可验证硬件绑定密钥、应用身份、挑战及递增计数器；Mac 证书中的 ACL Blob OID 可表达 Secure Enclave 对密钥强制执行的 Full Security/SIP 条件。它比普通客户端自行上报“SIP已开启”提供更强依据，但不能被写成所有运行行为都真实；同一官方讲解也指出被攻陷设备可能充当证明代理，需要风险分析。

当前本机 26.6.2/SDK 26.5 不能用来验证 macOS 27 新增支持。已查资料没有确认 Mac App Store、Developer ID 等全部分发渠道的精确支持组合，因此渠道、硬件、签名配置、生产环境和验证服务应列为接入前待核验项。没有申请或启用该服务。

## 6. 建议的验证矩阵与准入结论

下列是基于上述资料的工程建议，不是已经完成的验证结果：

| 验证阶段 | 必测行为 | 通过标准 |
| --- | --- | --- |
| 正常基线 | 原版 UU 可连接、可输入、可看到动态画面 | 建立真实端到端基线，避免把本来故障计为防护成功 |
| AAC 启动 | 已连接会话、新连接、GUI 重开、后台重启 | 等开始回调后逐项验证；记录是拒绝连接、停止帧、隐藏内容还是其他行为 |
| AAC 中断/结束 | 正常交卷、取消、系统中断、客户端崩溃 | 停止敏感输出；恢复系统状态后再次真实连接，不能只检查 job 存在 |
| ES 独立验证 | 禁止程序的新执行、策略启用前已运行实例、事件超时 | 明确新执行授权和存量会话处理的不同；策略失效触发考试状态降级 |
| 管理员对抗 | 停用普通 helper、撤销权限、注销重启、断网 | 区分本机可见事件与服务端失联记录；不将普通断网直接等同于作弊 |
| 版本与辅助需求 | Intel/Apple silicon、目标 macOS、输入法、辅助功能、原始帧录像 | 按支持矩阵发布能力，不将单机成功推广为全覆盖 |

AAC/ES 审批只应按公开可验证条件规划。公开资料未给出保证审批时间或通过率；准备 Team ID、Bundle ID、真实考试流程、恢复方案和分发计划是建议材料，不是对登录后申请表全部必填项的断言。申请获批前，可以完成自有应用状态机、服务端异常记录和模拟测试，但不能把未授权 AAC/ES 的纸面方案标成实机防护已完成。
