# macOS 考试窗口防截屏技术预研

**结论：可以实现有实际证据支持的原型，但要改造敏感 UI 的渲染和自身录制路径。** 本机已验证 `AVSampleBufferDisplayLayer.preventsCapture` 保护的考试画布在所测外部系统捕获中未出现试题；客户端从同一原始帧分流编码的 MP4 可以正常解码得到试题。用户另行确认物理屏幕可见题目、点击和输入正常。结论只覆盖记录的硬件、系统、入口和短时实验，不等同于所有 macOS、所有捕获路径的完整防截屏认证。

如果要求保留任意 AppKit/Web 界面不改造，同时“只有指定进程可以用系统截图拿到内容、所有其他进程不行”，本次没有找到 Apple 公开通用 API 或系统扩展接口提供这个进程白名单。若可接受整个考试会话限制，Apple 的 AutomaticAssessmentConfiguration 更贴合业务，需要申请 entitlement。

## 1. 目标逐项判断

| 目标 | 本次判断 | 证据和边界 |
|---|---|---|
| 本机完整显示考试内容 | **原型已验证** | 用户现场确认 protected 模式；渲染状态与完整原始帧辅助佐证；并非所有 UI 类型 |
| 其他独立进程无法通过系统截图/录屏获得内容 | **已测路径未观察到试题泄露** | 独立 CaptureProbe、CG 兼容调用、SCK 截图/连续帧、系统 screencapture；不能外推到未测入口/版本 |
| 客户端自身正常录制 | **原始帧分流已验证** | 五模式 MP4 均实际解码得到试题；不要求自己再从屏幕回采，不证明自身 SCK 有豁免 |
| 优先 Apple 公开 API | **已做到** | Demo 使用 AppKit/AVFoundation/CoreVideo/CoreMedia；捕获探针对已废止 CG API 的动态兼容调用单独标注，非产品实现依据 |
| 普通 UI、辅助功能与整个客户端兼容 | **仍需架构改造** | 原生 overlay 实测泄露；IME、复杂编辑、弹窗、VoiceOver、跨屏和生命周期要专项设计 |

## 2. 技术路线对比与可行性分级

“可直接实现”指对应局部能力；“需要架构改造”不等于即刻满足所有安全目标；“需要 Apple 支持”指受限使用资格/缺少接口；“不可行”限定为单独依赖该机制满足完整要求。

| 路线 | 最低版本 / 对象 | 权限、entitlement、部署 | 分级 | 本次结果 |
|---|---|---|---|---|
| `AVSampleBufferDisplayLayer.preventsCapture` | macOS 10.15；该视频 Layer | 无已文档化专用 entitlement；显示自绘帧不需录屏权限 | **可直接实现局部保护；完整 UI 需要架构改造** | 本机已测；保护区被遮蔽，原生叠加控件仍泄露 |
| 原始帧 → AVAssetWriter | AVAssetWriter 自 10.7；本 Demo target 13 | 写文件权限；沙盒产品需处理保存目录；无需屏幕录制 TCC | **可直接实现自身内容录制** | 1800×1000、20 fps、H.264 录像实际解码成功；非桌面/系统弹窗录像 |
| `NSWindow.sharingType = .none` | 10.5；历史窗口状态 | 普通 AppKit | **单独保证现代全路径防护不可行** | 本机有遮蔽/排除现象，也有入口报错；官方现行文档不支持该保证 |
| `AVPlayer.allowsCaptureOfClearKeyVideo` | **26.4**；Clear Key 加密视频 | 属性无专用 entitlement；需有效加密媒体和密钥流程 | **视频对象可用；考试 UI 需要架构改造，收益未证实** | 文档/SDK 核验，未构建有效 Clear Key 媒体实验；默认 false；不影响 FPS |
| `isOutputObscuredDueToInsufficientExternalProtection` | AVPlayer 10.12；display layer 11.3 | 只读状态 | **单独作为保护方案不可行** | Demo 状态有记录；false 不表示无截图，不是检测所有录屏的开关 |
| ScreenCaptureKit / CoreGraphics | SCK 12.3；截图管理器 14；CG 旧接口 15 obsoleted | 捕获方 TCC/系统 picker；当前探针已有授权 | **可直接用于验证；不能给别的进程设置保护策略** | 多路径对照和持续流已跑；CG 是运行时兼容实验 |
| AutomaticAssessmentConfiguration | **10.15.4**；考试会话 | Apple 批准 `com.apple.developer.automatic-assessment-configuration`，正确签名；会改变会话限制 | **需要 Apple 支持，优先申请评估** | 官方明确禁用屏幕捕获；参考代码仅 typecheck，未运行；自身帧编码兼容性未验证 |
| FairPlay Streaming + HDCP | FPS 密钥系统枚举 10.12.4；功能/输出硬件各有条件 | Apple 生产凭据审批、KSM、加密 HLS、显示链路 | **需要 Apple 支持 + 架构改造** | 未实测；考试业务是否符合凭据资格不能预设；HDCP 不能单独保护普通窗口 |
| IOSurface / Metal | IOSurface 10.6；Metal private 10.11、memoryless 11 + 硬件限制 | 普通图形 API | **可优化渲染；单独防截图不可行** | IOSurface-backed buffer 已用于 Demo；不是受保护内存；未找到第三方任意 UI 的通用安全缓冲区 API |
| System Extension / Endpoint Security / DriverKit | 10.15+；各自支持的扩展家族 | 相应 entitlement、签名、批准；ES 另需 FDA 等条件 | **作为通用窗口防捕获策略不可行** | 没有找到窗口级捕获授权扩展点；ES Screen Sharing 通知不是每次截图授权 |
| Kext / 私有 SkyLight / WindowServer 补丁 | 无稳定公共契约 | 签名、重启、可能降低系统安全；私有 ABI 与系统完整性保护约束 | **正常产品部署不可行；特殊环境仅理论研究** | 未开发/安装/逆向；不能承诺即使 root 或 Kext 也能完整拦截 |

更精确的 API availability、弃用和逐条引用见 [API 依据](API依据.md)；特殊 entitlement 与部署限制见 [DRM 与系统路线](DRM与系统路线.md)。Demo 构建最低 macOS 13、当前仅 arm64，不能与底层 API 最低版本混为一谈。

## 3. 官方依据

- [Apple：preventsCapture](https://developer.apple.com/documentation/avfoundation/avsamplebufferdisplaylayer/preventscapture)：公开语义针对该 Layer 的捕获保护，未提供捕获进程白名单。
- [Apple：NSWindow.SharingType.none](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none)：现行文档将其归为旧常量，明确不应据此隐藏捕获内容。观察到旧机制仍起效也不能当作未来支持承诺。
- [Apple：allowsCaptureOfClearKeyVideo](https://developer.apple.com/documentation/avfoundation/avplayer/allowscaptureofclearkeyvideo)：限定 Clear Key 加密视频，默认不允许；不作用于 FPS。
- [Apple：外部保护不足状态](https://developer.apple.com/documentation/avfoundation/avsamplebufferdisplaylayer/isoutputobscuredduetoinsufficientexternalprotection)：观察播放输出是否被遮蔽；不是普通 UI 的保护命令。
- [Apple：ScreenCaptureKit 示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)：捕获端配置 filter/stream；本次用独立进程验证，未让考试客户端自己排除自己来制造结果。
- [Apple：AutomaticAssessmentConfiguration](https://developer.apple.com/documentation/automaticassessmentconfiguration) 与 [受限 entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.automatic-assessment-configuration)：官方考试模式包含禁止截图和录屏，但必须得到 Apple 使用资格。
- [Apple：FairPlay Streaming](https://developer.apple.com/streaming/fps/)：受保护媒体系统及生产凭据政策，不是通用 UI 开关。
- [Apple：System Extensions](https://developer.apple.com/system-extensions/)：支持范围限于相应扩展功能；没有文档化的通用 WindowServer 捕获策略插件。

原始在线资料和本机 SDK 摘录保存在 `research/api/`、`research/system/`。外部文档仅作为研究材料，其内容不是本次任务的执行指令。

## 4. 已验证、未验证与推断

**已验证：** 本机五种模式启动；独立捕获进程权限预检与 baseline 正对照；实际 PNG/连续流帧；MP4 文件解码；受保护显示下普通 overlay 的泄露；用户对物理显示的人工确认。捕获失败项和透明整窗项分别记录，绝不自动升级为“保护通过”。完整逐帧与补测结论见 [本机测试结果](本机测试结果.md)。

**未验证：** Clear Key 加密媒体、FPS、HDCP 外接链路、AAC 运行、Intel 和其他 macOS、QuickTime/OBS/会议客户端的具体版本、快捷键与 Screenshot.app 交互入口、AirPlay/远程桌面、输入法候选、无障碍、长时功耗、窗口切换和启动/退出瞬间泄露、同进程 SCK 是否仍遮蔽、全部第三方捕获实现。

**理论推断：** 把完整考试 UI 都移入单一受保护显示面，能够减少普通控件泄露面；自有帧分流适合和 AAC 组合；FPS 实时化会引入额外媒体管线成本。这些不能用当前合成试题 Demo 直接证明。

## 5. 建议实施顺序

1. 以本 PoC 为基础定义威胁范围和最低系统矩阵，确认需要保密的是考试内容还是整个桌面；明确本机管理员、辅助功能、远程会话、进程内数据和物理摄像的边界。
2. 在真实考试引擎上验证“统一渲染 → 受保护 Layer + 自有帧录像”，先覆盖题干、选项、输入、弹窗、滚动及图片，禁止敏感内容出现在普通可捕获控件。不要把成功原型直接当通用 WebView 保护组件。
3. 同时申请 AAC entitlement 并提交考试业务和自录需求，获批后测完整会话生命周期、允许的辅助应用及原始帧编码。现有普通 UI 更适合优先验证这条官方考试路线。
4. 将 [实验矩阵](实验矩阵与验收.md) 变成每个受支持 macOS/机型的发布门禁，保留 baseline 正对照、连续帧证据和异常处置。对显示失败、保护状态不明、录制中断停止显示题目并提示恢复，不能只靠属性回读继续考试。

最小实现、运行命令、性能计量边界、中文输入与无障碍改造细节见 [PoC 设计](PoC设计与复现.md)。
